# Практическая работа: Алгоритмы стандартной библиотеки шаблонов (STL Algorithms)

## 1. Философия STL-алгоритмов: разделение данных и операций

В предыдущей практической работе (папка 10) было показано, что контейнеры
STL (vector, list, map и т.д.) предоставляют унифицированный доступ к
данным через итераторы. **Алгоритмы STL** (`sort`, `find`, `count`,
`reverse`, `for_each`, `copy`, `transform` и десятки других) — это вторая
половина этой архитектуры: обобщённые функции, оперирующие **парой
итераторов** `[begin, end)`, а не конкретным контейнером.

```cpp
sort(v.begin(), v.end());       // сортировка vector
sort(arr, arr + n);             // сортировка обычного C-массива — тем же алгоритмом!
```

Это возможно благодаря тому, что `sort` не знает и не должен знать, с
каким контейнером работает — он оперирует исключительно интерфейсом
итератора (`*it`, `++it`, `it1 - it2` для итераторов произвольного
доступа). Такое разделение — практическое воплощение принципа **"N
контейнеров × M алгоритмов вместо N×M реализаций"**: без обобщённых
алгоритмов пришлось бы писать отдельную сортировку для массива, отдельную
для списка и т.д. С алгоритмами STL — один `sort`, работающий с любым
контейнером, чьи итераторы поддерживают произвольный доступ.

## 2. Лямбда-функции — язык для алгоритмов

Многие алгоритмы (`count_if`, `find_if`, `sort` с компаратором, `for_each`,
`transform`) принимают **функциональный объект** — что-то вызываемое с
определённой сигнатурой. Начиная с C++11 для этого чаще всего используются
**лямбда-выражения**:

```cpp
[](int x) { return x % 2 == 0; }
```

Синтаксис `[]( параметры ) { тело }` создаёт безымянный функциональный
объект "на лету", без необходимости объявлять отдельную именованную
функцию или класс-функтор где-то ещё в коде. Квадратные скобки `[]` —
список захвата (что из окружающего контекста доступно внутри лямбды; в
Задании 5в `[average](int g) { return g > average; }` — лямбда захватывает
внешнюю переменную `average` по значению, чтобы использовать её внутри).

### Почему параметр иногда `int x`, а иногда `int& x`

В Задании 3 первая лямбда для `for_each` принимает `int x` (по значению) —
она только **читает** элемент, чтобы вывести его квадрат, изменять исходный
вектор не нужно. Вторая лямбда `[](int& x) { x += 1; }` принимает **по
ссылке** — она обязана изменить сам элемент вектора, а не его копию. Если
бы вторая лямбда тоже принимала по значению, `for_each` передавал бы в неё
копию каждого элемента, изменение которой никак не отразилось бы на
исходном векторе — типичная ошибка новичков при попытке "изменить
элементы через `for_each`".

## 3. Сложность алгоритмов и почему она важна

| Алгоритм | Сложность | Комментарий |
|---|---|---|
| `sort` | `O(n log n)` | Реализован как интроспективная сортировка (introsort — гибрид quicksort/heapsort/insertion sort) |
| `find`, `find_if` | `O(n)` | Линейный перебор — не может быть быстрее без дополнительной структуры (например, `set`/`map`, дающих `O(log n)`) |
| `count`, `count_if` | `O(n)` | Обязательный проход по всем элементам |
| `reverse` | `O(n)` | Обмен элементов с концов к середине, `n/2` обменов |
| `copy`, `copy_if`, `transform` | `O(n)` | Один линейный проход |

Важное практическое следствие: если данные нужно **искать многократно**,
разовый линейный `find` (`O(n)` на каждый вызов) — плохой выбор; лучше
один раз построить `set`/`unordered_set` (`O(n log n)` или `O(n)` на
построение) и затем искать за `O(log n)`/`O(1)` — это прямая связь с темой
предыдущей практической работы про контейнеры STL (папка 10) и с темой
анализа сложности алгоритмов (папка 14).

## 4. Разбор ключевых приёмов из заданий

### `back_inserter` — итератор-адаптер для контейнеров без известного
размера заранее (Задание 4)

`copy_if(src.begin(), src.end(), back_inserter(destEven), predicate);`

`back_inserter(container)` создаёт специальный **выходной итератор**,
который при каждой попытке "записать" в него (`*it = value;`) вызывает
`container.push_back(value)`. Это решает проблему: `copy`/`copy_if`,
как и большинство алгоритмов, ожидают, что итератор назначения уже
указывает на существующую, достаточно большую область памяти — обычный
`dest.begin()` не может добавлять новые элементы, только перезаписывать
существующие. `back_inserter` обходит это ограничение, позволяя копировать
**неизвестное заранее** количество элементов (например, только те, что
прошли фильтр) в изначально пустой контейнер.

### `transform` — применение функции с записью результата отдельно от
чтения (Задание 4)

`transform` похож на `for_each`, но принципиально отличается: `for_each`
предназначен для **побочных эффектов** (вывод на экран, изменение элемента
по ссылке "на месте"), а `transform` **порождает новую последовательность**
результатов применения функции, записывая её в отдельный диапазон
назначения (который может как совпадать с исходным, так и быть другим
контейнером — как `squares`, отдельный от `numbers`).

### `unique` — удаление подряд идущих дубликатов, а не всех дубликатов
(Задание 5а)

Частая ошибка новичков — считать, что `unique(v.begin(), v.end())` удаляет
**все** дубликаты из произвольного вектора. На самом деле `unique` удаляет
только **подряд идущие** повторы, "сдвигая" уникальные элементы в начало
диапазона и возвращая итератор на новый логический конец (при этом
физический размер контейнера не меняется — "хвост" после этого итератора
содержит "мусорные" остатки исходных данных). Поэтому для полного удаления
дубликатов вектор нужно **сначала отсортировать**, чтобы одинаковые
значения оказались рядом, а затем вызвать `unique` — именно так и сделано
в `zadanie5a_statistics.cpp`.

### Нахождение самого частого элемента без хэш-таблицы (Задание 5а)

После сортировки одинаковые элементы стоят подряд, поэтому "самый частый
элемент" можно найти одним линейным проходом, подсчитывая длину каждой
"серии" одинаковых значений — альтернатива построению `map<int, int>`
счётчиков, не требующая дополнительной памяти под словарь (компромисс
"время предварительной сортировки `O(n log n)`" против "память под
хэш-таблицу и один линейный проход `O(n)`" — типичный пример компромисса
время/память, разбираемого подробно в практической работе про сложность
алгоритмов, папка 14).

### Сортировка с пользовательским компаратором (Задания 5б, 6)

`sort` по умолчанию использует `operator<`, но принимает третий,
необязательный аргумент — компаратор, задающий произвольный критерий
порядка:

```cpp
sort(longWords.begin(), longWords.end(),
     [](const string& a, const string& b) { return a.length() < b.length(); });
```

То же самое используется в `max_element` (Задание 6) — по умолчанию он
ищет максимум по `operator<`, но для `struct Student`, у которого нет
встроенного оператора сравнения, обязательно нужно передать компаратор,
явно объясняющий, что "максимум" здесь означает "по полю `gpa`".

## 5. Реальные области применения

- **Обработка данных и аналитика**: подсчёт статистики (частоты, средние,
  медианы — Задание 5а) — базовая операция в любой системе анализа данных,
  ровно то, чем будет заниматься мини-проект в практической работе №13
  (папка 13).
- **Фильтрация и трансформация коллекций**: `copy_if` + `back_inserter` +
  `transform` — идиоматичный способ реализовать в C++ то, что в других
  языках называется `filter`/`map` (функциональное программирование).
- **Сортировка бизнес-сущностей по разным критериям**: `sort` с разными
  лямбда-компараторами (по GPA, по имени — Задание 6) — стандартный подход
  к сортировке таблиц в UI, отчётах, административных панелях.
- **Валидация данных**: `find_if`, `count_if` (Задание 5в: поиск первой
  неудовлетворительной оценки) — типовой паттерн проверки бизнес-правил
  над коллекцией записей (например, "есть ли хоть один просроченный
  платёж").

## 6. Ответы на вопросы для защиты практической работы

**Что такое алгоритмы STL? Какие категории алгоритмов вы знаете?**
Это обобщённые функции стандартной библиотеки C++, оперирующие парами
итераторов, а не конкретным типом контейнера. Категории: немодифицирующие
(`find`, `count`, `for_each` — не изменяют исходные данные),
модифицирующие (`copy`, `transform`, `reverse` — изменяют или создают
новую последовательность), сортирующие (`sort`, `partial_sort`), численные
(`accumulate`, `inner_product` из `<numeric>`) и другие.

**Как отсортировать вектор в порядке убывания?**
Передать третьим аргументом функтор `greater<T>()`
(`sort(v.begin(), v.end(), greater<int>());`) либо лямбда-компаратор
`[](int a, int b){ return a > b; }`.

**Как найти элемент в векторе с помощью find()?**
`auto it = find(v.begin(), v.end(), value);` — возвращает итератор на
первое вхождение значения либо `v.end()`, если значение не найдено; для
проверки результата всегда сравнивают итератор с `v.end()`.

**В чём разница между find() и find_if()?**
`find` ищет точное значение (сравнение через `operator==`). `find_if`
принимает предикат (функцию/лямбду, возвращающую `bool`) и находит первый
элемент, для которого предикат истинен — используется, когда критерий
поиска сложнее простого равенства (например, "первое число больше 100").

**Как подсчитать количество элементов, удовлетворяющих условию?**
С помощью `count_if(begin, end, predicate)` — количество, а не позицию,
элементов, для которых предикат возвращает `true`. `count(begin, end, val)`
— частный случай для подсчёта точных совпадений со значением.

**Как развернуть последовательность?**
`reverse(begin, end)` меняет местами элементы с концов диапазона к центру
за `O(n)` — работает для любого двунаправленного или более сильного
итератора (`vector`, `list`, `deque`, но не для однопроходных потоковых
итераторов).

**Для чего используется for_each()?**
Для применения произвольной функции/лямбды к каждому элементу диапазона —
как правило, ради побочного эффекта (вывод, накопление во внешнем
состоянии, изменение элемента "на месте" через параметр-ссылку).

**Как скопировать элементы из одного контейнера в другой?**
`copy(src.begin(), src.end(), dest.begin())`, если контейнер назначения
уже имеет достаточный размер, либо `copy(src.begin(), src.end(),
back_inserter(dest))`, если размер заранее неизвестен и элементы должны
добавляться динамически.

**В чём разница между copy() и copy_if()?**
`copy` копирует **все** элементы диапазона без исключений. `copy_if`
принимает дополнительно предикат и копирует только те элементы, для
которых предикат истинен, пропуская остальные.

**Что такое лямбда-функция и как она используется в алгоритмах STL?**
Безымянный функциональный объект, определяемый прямо в месте
использования синтаксисом `[захват](параметры) { тело }`. В алгоритмах
STL лямбды передаются как предикаты (`find_if`, `count_if`), компараторы
(`sort`) или функции для применения к каждому элементу (`for_each`,
`transform`), избавляя от необходимости объявлять отдельные именованные
функции или классы-функторы для одноразовой логики.
