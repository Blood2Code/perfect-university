# Практическая работа №3: ООП — классы и объекты

## 1. Класс и объект: базовая абстракция ООП

**Класс** — это пользовательский тип данных, объединяющий в единую сущность
данные (поля/члены-данные) и операции над этими данными (методы). Это
реализация идеи **инкапсуляции** — объединения состояния и поведения в одном
"кирпичике" программы.

**Объект** — это конкретный экземпляр класса, реально существующий в памяти
и обладающий собственным набором значений полей. Отношение класса к объекту
такое же, как отношение чертежа дома к конкретному построенному дому:
чертёж (класс) один, а домов (объектов) по этому чертежу можно построить
сколько угодно, и каждый из них независимо стоит на своём месте (занимает
свою область памяти) и может отличаться деталями (значениями полей).

Технически при компиляции класс не занимает памяти сам по себе — память
резервируется только под объекты. Методы класса, в свою очередь, не
дублируются для каждого объекта: в памяти существует одна копия кода
метода, а компилятор неявно передаёт указатель на конкретный объект
(`this`) в качестве скрытого первого аргумента при вызове.

## 2. Инкапсуляция и модификаторы доступа

**Инкапсуляция** — сокрытие внутреннего устройства объекта от внешнего кода
и предоставление доступа только через контролируемый публичный интерфейс.
Три модификатора доступа в C++:

| Модификатор | Область видимости |
|---|---|
| `public` | Доступен из любого места программы |
| `private` | Доступен только внутри методов самого класса |
| `protected` | Доступен внутри класса и его производных классов (актуально для наследования, папка 4) |

### Зачем нужны геттеры/сеттеры, если поля можно сделать `public`?

На первый взгляд `getX()`/`setX()` выглядят избыточно — они просто читают и
пишут поле. Но их ценность раскрывается позже, когда появляется
**валидация** и **инварианты класса**. Например, в `BankAccount::deposit()`
и `withdraw()` (Задание 3) сеттер не просто присваивает значение, а
проверяет условие `amount > 0` и `amount <= balance` — если бы `balance`
был публичным полем, любой код мог бы установить его в отрицательное
значение или обойти проверку баланса, что нарушило бы логическую
целостность объекта. Инкапсуляция гарантирует, что **единственный путь**
изменения состояния объекта проходит через код, который сам класс
контролирует.

Кроме того, геттеры/сеттеры дают свободу изменить внутреннее представление
данных (например, заменить `double balance` на структуру с историей
транзакций), не трогая внешний интерфейс класса и не ломая код,
использующий этот класс — это называется **инкапсуляционный барьер**
(information hiding).

## 3. Конструкторы

**Конструктор** — специальный метод, вызываемый автоматически при создании
объекта, отвечающий за приведение объекта в валидное начальное состояние
(инициализация полей, выделение ресурсов). В C++ существует несколько видов:

- **Конструктор по умолчанию** (`Point()`) — вызывается, когда объект
  создаётся без аргументов.
- **Конструктор с параметрами** (`Point(double x, double y)`) — позволяет
  задать начальное состояние явно.
- **Конструктор копирования** (`Rectangle(const Rectangle&)`) — вызывается,
  когда новый объект создаётся как копия существующего (`Rectangle r2 = r1;`,
  либо при передаче объекта в функцию по значению).

### Почему в классе с "сырой" динамической памятью обязателен свой
конструктор копирования (Задание 2)?

Если конструктор копирования не определён явно, компилятор генерирует его
автоматически, и по умолчанию он выполняет **поверхностное копирование**
(shallow copy) — то есть копирует значение указателя `data`, а не то, на что
он указывает. В результате оба объекта (оригинал и копия) начинают владеть
**одним и тем же** блоком памяти. При разрушении первого объекта его
деструктор вызовет `delete[] data`, и указатель второго объекта станет
"висячим" (dangling pointer) — обращение к нему приведёт к неопределённому
поведению, а повторный `delete[]` в деструкторе второго объекта вызовет
двойное освобождение памяти (double free).

`DynamicArray` в Задании 2 решает это через **глубокое копирование** (deep
copy): конструктор копирования выделяет **новый** блок памяти и построчно
копирует значения элементов, а не адрес. После этого оба объекта полностью
независимы: изменение одного не затрагивает другой (что явно
демонстрируется в `main()`: изменение `arr1[0]` не влияет на `arr2`).

## 4. Деструкторы

**Деструктор** (`~ClassName()`) вызывается автоматически при уничтожении
объекта (выход из области видимости для стекового объекта, вызов `delete`
для объекта в куче, разрушение контейнера, элементом которого является
объект). Его основная задача — освободить ресурсы, захваченные объектом за
время его жизни: динамическую память, файловые дескрипторы, сетевые
соединения. Именно деструктор реализует идиому RAII, разобранную подробно
в практической работе про динамическую память (папка 2).

Для класса без динамических ресурсов (например, `Point`) явный деструктор
не нужен: сгенерированный компилятором деструктор просто вызывает
деструкторы полей по очереди, и этого достаточно.

## 5. Список инициализации членов класса (Задание 4)

Список инициализации — это конструкция вида:

```cpp
Employee(int empId, ...) : id(empId), companyName(company), ... { ... }
```

Она инициализирует поля **до** входа в тело конструктора. Это не просто
стилистическое предпочтение — для некоторых категорий полей это
**единственный возможный способ** инициализации:

1. **Константные поля** (`const int id`) — константу нельзя присвоить
   значение после её создания (`id = empId;` в теле конструктора было бы
   присваиванием уже созданной константе — ошибка компиляции). Список
   инициализации инициализирует поле в момент его создания, что для
   `const` разрешено.
2. **Ссылочные поля** (`const string& companyName`) — ссылка обязана быть
   привязана к объекту сразу при создании (см. разбор ссылок в папке 1) —
   присвоить ссылку "потом" в теле конструктора невозможно синтаксически.
3. **Поля-объекты без конструктора по умолчанию** — если у поля-объекта нет
   конструктора без аргументов, единственный способ его инициализировать —
   явно вызвать нужный конструктор в списке инициализации.

Важный нюанс: поля класса **инициализируются в порядке их объявления в
классе**, а не в порядке перечисления в списке инициализации — компилятор
может даже выдать предупреждение (`-Wreorder`), если эти порядки не
совпадают. Это стоит учитывать при наличии зависимостей между полями.

## 6. Оператор присваивания и правило трёх

Как и с конструктором копирования, если класс управляет ресурсом (например,
`data` в `DynamicArray`), автоматически сгенерированный `operator=` также
выполняет поверхностное копирование и приводит к тем же проблемам двойного
освобождения. **Правило трёх (Rule of Three)** гласит: если класс явно
определяет один из трёх специальных методов — деструктор, конструктор
копирования, оператор присваивания, — он почти наверняка должен определить
и два оставшихся, потому что все они управляют одним и тем же ресурсом.

Корректная реализация `operator=` (Задание 2, `DynamicArray::operator=`)
обязательно включает **проверку на самоприсваивание** (`if (this != &other)`):
без неё код `delete[] data;` удалил бы память объекта до того, как из неё же
попытались бы прочитать данные для копирования в `arr = arr;` — классическая
ошибка "use after free".

## 7. Реальные примеры применения этих концепций

- **Валидация в сеттерах** (как в `BankAccount`) — основа любой бизнес-логики
  в банковских и финансовых системах: баланс, лимиты, транзакции всегда
  проверяются на уровне класса, а не полагаются на дисциплину вызывающего
  кода.
- **Список инициализации с константными полями** — идентификаторы записей в
  базах данных, неизменяемые after-конструкции конфигурации (`const`),
  внедрение зависимостей через ссылки (dependency injection).
- **Глубокое копирование** — любые классы-обёртки над буферами (изображения,
  аудиобуферы, строки до появления `std::string` с COW/SSO-оптимизациями)
  обязаны реализовывать её вручную либо делегировать управление контейнерам
  стандартной библиотеки.
- **Динамический массив с автоматическим ростом** (`Student::resize()`) —
  именно так изнутри устроен `std::vector`: удвоение вместимости при
  переполнении обеспечивает амортизированную сложность `O(1)` для
  добавления элемента.

## 8. Ответы на вопросы для защиты практической работы

**Что такое класс и объект в C++? В чём разница между ними?**
Класс — это описание (шаблон) пользовательского типа, объединяющего данные
и методы. Объект — конкретный экземпляр класса, реально существующий в
памяти со своими значениями полей. Класс один, объектов по нему может быть
создано сколько угодно.

**В чём отличие class от struct?**
Единственное синтаксическое отличие в C++ — модификатор доступа по
умолчанию: у `struct` все члены по умолчанию `public`, у `class` — `private`.
По соглашению `struct` используют для простых структур данных без
инкапсулированной логики, а `class` — когда есть инварианты и поведение,
которые нужно защищать через инкапсуляцию.

**Какие модификаторы доступа существуют в C++? Для чего нужен каждый из
них?**
`public` — открытый интерфейс класса, доступный извне. `private` — детали
реализации, доступные только методам самого класса, обеспечивают
инкапсуляцию. `protected` — как `private`, но доступен ещё и производным
классам, что нужно для наследования, когда потомок должен иметь доступ к
внутреннему состоянию родителя.

**Что такое инкапсуляция и как она реализуется в C++?**
Инкапсуляция — сокрытие внутреннего состояния объекта и предоставление
доступа к нему только через контролируемый публичный интерфейс методов.
Реализуется через модификаторы доступа (`private`/`protected`) в сочетании
с публичными методами (геттеры, сеттеры, бизнес-методы), которые могут
проверять и поддерживать инварианты класса.

**Что такое конструктор? Какие виды конструкторов вы знаете?**
Конструктор — специальный метод, вызываемый автоматически при создании
объекта для его инициализации. Виды: конструктор по умолчанию (без
параметров), конструктор с параметрами, конструктор копирования, а также
конструктор перемещения (move-конструктор, начиная с C++11).

**Что такое конструктор копирования и когда он вызывается?**
Это конструктор, принимающий ссылку на объект того же класса
(`ClassName(const ClassName& other)`) и создающий новый объект как его
копию. Вызывается при инициализации нового объекта существующим
(`T b = a;`), при передаче объекта в функцию по значению и при возврате
объекта из функции по значению (если не применяется оптимизация
копирования — copy elision).

**Что такое деструктор? Для чего он нужен?**
Метод `~ClassName()`, вызываемый автоматически при уничтожении объекта.
Нужен для освобождения ресурсов, захваченных объектом за время жизни:
динамической памяти, файлов, сетевых соединений и т.п.

**В чём разница между инициализацией в списке инициализации и присваиванием
в теле конструктора?**
Список инициализации создаёт поле сразу с нужным значением (один шаг).
Присваивание в теле конструктора сначала создаёт поле конструктором по
умолчанию, а затем присваивает ему новое значение (два шага) — менее
эффективно, а для констант, ссылок и объектов без конструктора по умолчанию
вообще невозможно.

**Почему константные поля и ссылки должны инициализироваться в списке
инициализации?**
Потому что константу нельзя изменить после её создания, а присваивание в
теле конструктора — это уже изменение существующего значения, а не
инициализация. Ссылка обязана быть привязана к конкретному объекту в
момент создания и не может быть "переприсвоена" позже — синтаксис
присваивания ссылке в C++ означает изменение объекта, на который она
указывает, а не перепривязку самой ссылки.

**Что такое правило трёх (Rule of Three) и когда оно применяется?**
Правило гласит: если класс явно реализует один из трёх методов —
деструктор, конструктор копирования или оператор присваивания, — он,
скорее всего, должен реализовать и два других, поскольку это обычно
означает, что класс управляет ресурсом, требующим глубокого копирования и
корректного освобождения. Применяется всегда, когда класс содержит "сырые"
указатели на динамически выделенную память или другие неуправляемые
ресурсы.
