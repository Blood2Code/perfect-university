# Практическая работа №10: Шаблоны классов (Class Templates)

## 1. Проблема, которую решают шаблоны

Представим, что нужно реализовать структуру данных "пара значений" для
`int`, для `double`, для `string`. Без шаблонов пришлось бы писать три
почти идентичных класса (`IntPair`, `DoublePair`, `StringPair`),
отличающихся только типом полей — классический случай **дублирования
кода**, нарушающий принцип DRY (Don't Repeat Yourself). Более того, при
обнаружении ошибки в логике пришлось бы чинить её сразу в трёх местах.

**Шаблон класса (class template)** — механизм C++, позволяющий описать
класс **параметрически**, с типом (или типами), который подставляется
компилятором отдельно для каждого конкретного использования:

```cpp
template <typename T>
class Pair {
    T first, second;
    ...
};

Pair<int> p1(1, 2);        // компилятор генерирует Pair<int>
Pair<string> p2("a", "b"); // и отдельно — Pair<string>
```

## 2. Как это работает "под капотом": инстанцирование шаблонов

Важно понимать: шаблон сам по себе **не является кодом**, который можно
скомпилировать в машинные инструкции — это "рецепт" для генерации кода.
Компилятор не генерирует код класса `Pair<T>` вообще; вместо этого при
первом использовании `Pair<int>` в исходном тексте компилятор **создаёт
(инстанцирует)** конкретный класс `Pair<int>`, подставляя `int` вместо
`T` всюду в определении, и уже этот сгенерированный класс компилируется в
обычный машинный код. Если в программе используются `Pair<int>` и
`Pair<string>`, компилятор фактически создаёт **два независимых класса**,
просто по общему шаблону.

Этот процесс называется **инстанцированием шаблона на этапе компиляции**
(compile-time instantiation), и он объясняет несколько практических
следствий:

1. **Шаблоны, как правило, определяются целиком в заголовочных файлах**
   (или, как в учебных примерах, прямо в одном `.cpp`), а не разделяются на
   `.h`/`.cpp`, как обычные классы — компилятору нужно видеть полное
   определение шаблона в каждой единице трансляции, где он используется,
   чтобы выполнить инстанцирование.
2. **Ошибка типа обнаруживается только при инстанцировании конкретным
   типом**, а не при определении самого шаблона — например, `Pair<T>` с
   методом `T + T` скомпилируется без проблем для `Pair<int>`, но выдаст
   ошибку компиляции для типа без оператора `+`, причём ошибка укажет
   именно на место использования, а не на определение шаблона.
3. **Не бывает накладных расходов во время выполнения** — раз каждый тип
   генерирует отдельный, полностью независимый код, шаблоны не используют
   динамическую диспетчеризацию (в отличие от полиморфизма через
   виртуальные функции). Это ещё одно проявление принципа "нулевой
   стоимости абстракции", уже упоминавшегося в практической работе про
   умные указатели (папка 2).

## 3. Разбор заданий

### Задание 1 — Pair<T>: один параметр типа

Простейший случай: оба поля (`first`, `second`) одного типа `T`. Метод
`swap()` работает одинаково для любого `T`, потому что использует лишь
операцию присваивания, доступную у всех типов, поддерживаемых как
шаблонный параметр (в том числе встроенных, вроде `int` и `char`, и
классов с определённым `operator=`, вроде `std::string`).

### Задание 2 — Array<T>: шаблон, управляющий динамической памятью

Это шаблонная версия идей из практической работы про классы (папка 3):
глубокое копирование, оператор присваивания, автоматическое удвоение
вместимости (`resize()`). Отличие только в том, что тип элементов — не
жёстко `int`, а параметр `T`, поэтому один и тот же код обслуживает и
`Array<int>`, и `Array<string>`, и `Array<double>` — компилятор
самостоятельно генерирует правильную версию `new T[capacity]` и
`data[i] = other.data[i]` для каждого конкретного `T`.

### Задание 3 — Triple<T1, T2, T3> и Pair2 с параметрами по умолчанию

Шаблон класса может принимать **несколько независимых параметров типа**
(`Triple<int, double, string>` — три *разных* типа для трёх полей). Кроме
того, параметрам шаблона, как и обычным параметрам функций, можно задать
**значение по умолчанию**:

```cpp
template <typename T1 = int, typename T2 = int>
class Pair2 { ... };

Pair2<> p1(10, 20);              // оба параметра — int (по умолчанию)
Pair2<string, double> p2(...);   // явно заданные типы
```

Синтаксис `Pair2<>` (пустые угловые скобки) означает "используй параметры
по умолчанию для всех неуказанных типов".

### Задание 4 — Полная специализация шаблона (Storage<bool>,
Storage<const char*>)

Иногда общая шаблонная реализация не подходит для конкретного типа —
например, для `bool` хотелось бы выводить "true (истина)"/"false (ложь)"
вместо стандартного `1`/`0`. **Полная специализация шаблона**
(`template <> class Storage<bool> { ... };`) позволяет предоставить
**полностью отдельную реализацию класса** для конкретного типа —
компилятор, встретив `Storage<bool>`, использует именно эту специализацию
вместо генерации из общего шаблона `Storage<T>`.

Специализация — не "переопределение метода" (как при наследовании), а
именно отдельное, самостоятельное определение класса: `Storage<bool>` и
`Storage<int>` не связаны никаким отношением наследования и никак не
разделяют код между собой, кроме одинакового пользовательского имени и
интерфейса. Именно поэтому в специализации можно добавить метод,
которого нет в общем шаблоне (`invert()` для `bool`, `getLength()` для
`const char*`) — это два разных класса с общим именем-шаблоном.

### Задание 5 — BoundedArray<T, N>: параметр-не-типа (non-type template
parameter)

```cpp
template <typename T, size_t N>
class BoundedArray {
    T data[N];   // N известно на этапе компиляции!
    ...
};
```

Здесь `N` — не тип, а **значение**, подставляемое как параметр шаблона.
Такие параметры называются **параметрами-не-типа** (non-type template
parameters) и должны быть известны на этапе компиляции (это могут быть
целые числа, перечисления, указатели/ссылки со статическим временем
жизни, а начиная с C++20 — и некоторые классы). Благодаря тому, что `N`
известно во время компиляции, `T data[N];` — это **массив фиксированного
размера на стеке**, а не куче (в отличие от `Array<T>` из Задания 2), что
даёт выигрыш в производительности (нет обращений к аллокатору) ценой
потери гибкости (размер нельзя изменить после компиляции). Это ровно та же
идея, что лежит в основе `std::array<T, N>` из стандартной библиотеки.

### Задание 6 — Matrix<T>: шаблон, инкапсулирующий `std::vector`

Полноценная реализация класса-матрицы, обобщённого по типу элементов.
Показательно, что внутри шаблон использует `std::vector<std::vector<T>>`,
а не "сырые" указатели — это иллюстрация того, что современный C++
предпочитает **строить новые абстракции поверх уже проверенных,
безопасных контейнеров**, а не переизобретать управление памятью каждый
раз заново (то же правило нуля, что и в практической работе про
динамическую память, папка 2).

## 4. typename vs class в объявлении шаблона

`template <typename T>` и `template <class T>` в объявлении шаблона
**полностью эквивалентны** — это исторический артефакт: ключевое слово
`class` использовалось для этой цели ещё до появления `typename` в языке,
и осталось для обратной совместимости. По современному соглашению `typename`
предпочтительнее, потому что явно говорит, что параметром может быть
**любой тип**, а не только пользовательский класс (можно подставить и
`int`, и `double`, и указатель).

## 5. Реальные области применения

- **Вся стандартная библиотека шаблонов (STL)** — `std::vector<T>`,
  `std::map<K, V>`, `std::unique_ptr<T>` — это шаблоны классов, изученные в
  данной работе, применённые в промышленном масштабе (см. практические
  работы про STL-контейнеры и алгоритмы, папки 10–11).
- **Обобщённые математические библиотеки** (линейная алгебра, физические
  движки): один и тот же код матрицы/вектора работает с `float`, `double`,
  комплексными числами без дублирования.
- **Обобщённые структуры данных в системном ПО**: буферы фиксированного
  размера (аналог `BoundedArray`) активно используются во встраиваемых
  системах (embedded), где динамическое выделение памяти нежелательно или
  запрещено (например, в реальном времени, real-time системах).
- **Политика типов (policy-based design) и метапрограммирование** —
  продвинутое использование шаблонов для генерации специализированного
  кода под конкретные требования без потери производительности во время
  выполнения.

## 6. Ответы на вопросы для защиты практической работы

**Что такое шаблоны классов в C++?**
Механизм, позволяющий описать класс с одним или несколькими
параметрами-типами, которые компилятор подставляет для генерации
конкретных классов при каждом отдельном использовании шаблона с
конкретным типом (или набором типов).

**Как объявить и использовать шаблон класса?**
Объявление начинается с `template <typename T>` (или с несколькими
параметрами `template <typename T1, typename T2>`) перед определением
класса, использующего `T` в качестве типа полей/параметров методов.
Использование — указание конкретного типа в угловых скобках:
`ClassName<int> obj(...);`.

**Что такое специализация шаблона? Приведите пример.**
Отдельная, самостоятельная реализация шаблона для конкретного типа,
отличная от общей (обобщённой) версии. Пример: `Storage<T>` в общем виде
выводит значение через `operator<<`, а специализация `Storage<bool>`
выводит вместо `1`/`0` слова "true (истина)"/"false (ложь)".

**Что такое параметр шаблона не типа (non-type template parameter)?**
Параметр шаблона, являющийся не типом, а значением, известным на этапе
компиляции (например, `size_t N` в `BoundedArray<T, N>`), который
используется, в частности, для задания размера массивов фиксированной
длины внутри шаблона.

**В чём разница между typename и class в объявлении шаблона?**
Синтаксически они эквивалентны в контексте `template <typename T>` /
`template <class T>` — оба означают "T — произвольный тип". Разница чисто
историческая; современный стиль предпочитает `typename`.

**Можно ли создавать шаблоны с несколькими параметрами?**
Да, шаблон класса может иметь произвольное количество параметров типов
(и/или параметров-не-типа), разделённых запятыми, например
`template <typename T1, typename T2, typename T3>`.

**Что такое частичная специализация шаблона?**
Специализация, в которой не все параметры шаблона зафиксированы
конкретным типом, а часть остаётся параметризованной — например,
`template <typename T> class Storage<T*> { ... };` специализирует
поведение для любого указателя, но всё ещё обобщено по типу, на который
указывает `T*`. В отличие от полной специализации (все параметры заданы
конкретно), частичная сохраняет часть обобщённости.

**Как работают шаблоны на этапе компиляции?**
Компилятор не генерирует код для самого шаблона — только при встрече
конкретного использования (`ClassName<ConcreteType>`) он подставляет тип
во все места шаблона и компилирует получившийся, полностью конкретный
класс. Этот процесс называется инстанцированием и происходит отдельно для
каждого уникального набора типов, использованного в программе.

**Какие ограничения есть у шаблонов?**
Определение шаблона обычно должно быть видно целиком в каждой единице
трансляции, где он используется (что заставляет размещать реализацию в
заголовочных файлах); ошибки типов обнаруживаются только при
инстанцировании, а не в определении; чрезмерное использование шаблонов
может увеличивать время компиляции и размер итогового бинарного файла
из-за генерации отдельного кода под каждую комбинацию типов (code bloat).

**Чем шаблоны классов отличаются от макросов?**
Макросы препроцессора выполняют текстовую подстановку до компиляции, не
понимая типов и синтаксиса C++, что делает их источником трудноуловимых
ошибок. Шаблоны — часть языка C++, полностью типобезопасны (компилятор
проверяет корректность типов при инстанцировании), поддерживают
перегрузку, специализацию и интегрированы с остальной системой типов и
диагностикой ошибок компилятора.
